# ADR Writing

Use this skill when a technical decision should be recorded for future maintainers.

## Procedure

1. State decision status, context, constraints, and decision drivers.
2. List options considered, including the current/default option.
3. Compare tradeoffs using repository evidence and operational constraints.
4. Record the chosen decision and why now.
5. Capture consequences, migration steps, validation, security impact, QA impact, release impact, and follow-up tasks.
6. Keep ADRs factual and durable; avoid meeting notes or speculation.

## Output

Return an ADR with title, status, context, decision, options, consequences, validation, risks, and follow-up tasks.
